Zer0Mail — Feature Roadmap Recommendations

Strategic feature picks based on the current Gmail-automation positioning.

Product framing. Zer0Mail today is a Gmail automation layer — rules engine + AI conditions + execution log + analytics. It is not a full email client, and these recommendations stay in that lane: deepen the rule/automation surface rather than competing with Superhuman or the Gmail UI itself.

High-conviction (build these first)

1. Rule dry-run / preview against past mail Trust

Before activating a rule, run it against the last 100–500 emails and show what would have happened. This is the #1 trust gap right now — users won't enable aggressive ARCHIVE or MARK_SPAM rules without it. Cheap to build, huge confidence unlock.

2. Bulk historical processing Onboarding

Currently rules only fire on incoming mail via Gmail watch. Let users say "apply this rule to my last 6 months of inbox." Turns the first-rule moment from "let's wait and see" into "1,847 emails archived, inbox down to 23." Killer onboarding.

3. One-click auto-unsubscribe + newsletter digest ARPU

Detect newsletters the user never opens; offer batch unsubscribe. Bundle the rest into a single daily/weekly "what you missed" email. This is the SaneBox/Mailman feature people actually pay for, and it slots cleanly into the existing rule action model as a new DIGEST action.

4. Outlook / Microsoft 365 support TAM

supportedProviders: ["google"] is a hard TAM ceiling. Microsoft Graph has equivalent webhook semantics to Gmail watch, so the rule engine doesn't need to change — just a second provider adapter. Even rough IMAP support after that opens the long tail.

5. Receipt / invoice extraction → Sheets / CSV / QuickBooks ARPU

A new rule action: EXTRACT_TO_SPREADSHEET. AI pulls vendor, amount, date, category from receipts and appends to a Google Sheet. Solopreneurs and contractors will pay Premium for this alone — tangibly worth more than $29/mo.

Strong second tier

6. Undo / "why did this match?" on the Activity page

ExecutionLog already records actions; add a 7-day undo window and an AI-generated explanation per match. Builds directly on the page that just shipped (commit 09eab03).

7. Webhook + Zapier action Platform

Rule action: POST to URL or "trigger Zap." Turns the rule engine into a platform (email → CRM, email → Linear ticket, email → Slack). Low effort, big ecosystem leverage.

8. Calendar / meeting AI

Parse meeting requests, detect conflicts against Google Calendar, propose times, RSVP. Pairs naturally with reply drafting.

9. Follow-up tracker

"You emailed Jane 5 days ago and she hasn't replied — nudge?" Inverts the product: not just inbound automation, but outbound accountability. Different muscle, same data.

10. Browser extension overlay in Gmail

"Create rule from this email" button inside the Gmail web UI. Massive shortcut — most rules are inspired by a specific annoying email the user just received.

Worth considering (lower ROI or more strategic)

  • Team plan + shared rule library — compliance/legal rules pushed org-wide; opens a B2B path.
  • Public rule marketplace — community moat and viral growth loop.
  • AI-drafted replies in your tone — fine-tune on sent folder; differentiator vs generic Smart Reply.
  • Auto-disable low-confidence rules with a confidence score on each rule — safety rail.
  • Inbox Zero streak / scoreboard — on-brand gamification given the product name.

Things to deliberately NOT build

  • A full compose / reply / thread UI. Don't compete with Gmail's own client; stay the layer on top.
  • Generic spam classifier. Gmail already does this — you'd be worse and it dilutes focus.

Open questions to sharpen scope

  • Is the near-term goal TAM expansion (Outlook), conversion (dry-run, historical processing), or ARPU (receipt extraction, team plan)? The right first 2–3 features differ a lot.
  • Any signal on whether free → Pro conversion is blocked by trust (no dry-run) or value (rules feel limited)? That decides #1 vs #5 as the lead bet.
