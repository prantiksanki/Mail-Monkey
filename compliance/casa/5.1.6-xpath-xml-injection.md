# CASA 5.1.6 — Data Validation and Sanitization: XPath/XML injection protection

> **Control 5.1.6 — Data Validation and Sanitization / Implement validation &
> input sanitization**
>
> *Protect against XPath or XML injection attacks.*
>
> **Deliverable**
> 1. Testing results from a scan completed using the ADA's Dynamic Application
>    Security Testing Guidance. Scanning may be performed by the developer or by
>    an authorized testing lab.

---

## Short answer (for the CASA portal)

This application does not parse or process XML content anywhere in its own
code. There is no XPath usage, no XML parser configured (safely or unsafely),
no SAML integration, and no DMARC aggregate-report (XML) ingestion. The
control is satisfied by absence: with no XPath queries ever constructed and no
XML parser ever invoked on application-reachable input, neither an
XPath-injection nor an XML-entity (XXE) surface exists.

---

## Deliverable — evidence

### No XML parsing library anywhere in application code

A search of every `package.json` across the monorepo, and of application
source directly, found no XML parsing library in use — no `DOMParser`,
`xml2js`, `fast-xml-parser`, `xmldom`, `libxmljs`, or `sax`. The only
`xml`-related strings anywhere in the repository are transitive lockfile
entries internal to the AWS SDK (`@aws-sdk/xml-builder`, used by the SES
client to serialize its own API requests) and to `jsdom` (a test-only
dependency) — neither is imported or invoked by any application code.

### No XPath usage

No `xpath` npm package, no `XPathEvaluator`, no DOM `.evaluate()` XPath calls
anywhere in the codebase. The only `.evaluate(` occurrences are Playwright's
`page.evaluate()` in end-to-end tests (`apps/web/tests/`) — this runs
arbitrary JavaScript inside a browser test context and has nothing to do with
XPath querying.

### Email pipeline: plain-text header parsing, not XML report ingestion

`packages/api/modules/mailboxes/lib/header-parser.ts:63-80` parses the
`Authentication-Results` email header — a plain-text, semicolon-delimited
RFC 8601 header (e.g. `spf=pass; dkim=pass; dmarc=pass`) — using a small regex
extractor:

```ts
const grab = (method: string): string | undefined => {
  const m = value.match(new RegExp(`\\b${method}=([a-z]+)`, "i"));
  return m ? m[1].toLowerCase() : undefined;
};
```

This extracts SPF/DKIM/DMARC *authentication verdicts* from plain header text
— it is unrelated to DMARC *aggregate reports*, which are a separate,
XML-formatted artifact some mail-security tools ingest. This application does
not ingest or parse DMARC aggregate reports. Email attachments
(`packages/api/modules/mailboxes/lib/email-parser.ts`) are handled as opaque
binary blobs referenced by `attachmentId` — there is no content-type branching
and no parsing of attachment bytes of any kind, XML or otherwise.

### No SAML integration

The app's single sign-on surface is OAuth 2.0/OIDC only (Google, Microsoft,
Zoom, Zoho — confirmed across several controls earlier in this session). SAML
metadata and assertion parsing, a classic XXE and XML-injection surface in
applications that support it, does not apply here — no SAML library or
SAML-related code exists anywhere in the repository.

### Sitemap generation — framework-serialized, not app-constructed XML

`apps/web/app/sitemap.ts` builds a typed `MetadataRoute.Sitemap` object using
Next.js's built-in sitemap convention; Next.js serializes this object to XML
internally at build/request time. The application itself never constructs or
manipulates a raw XML string, and the sitemap's content is static route
metadata (paths, priorities, last-modified dates) plus generated blog/legal
page metadata — no user-supplied input reaches it.

### On the listed deliverable (DAST scan)

As with the preceding 5.1.x controls, the checklist's deliverable text calls
for an external dynamic scan, tracked as the same open item under
[`3.1.1`](./3.1.1-urls-no-auth-material.md). Since this application presents
no XML-processing endpoint or feature at all, a DAST scan targeting
XPath/XML/XXE payloads has no surface to exercise here.
