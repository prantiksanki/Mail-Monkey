Azure OpenAI Migration Plan

StatusDeferred — not priority right now. Captured 2026-05-11 while setting up Azure App Service staging deployment.

1. Current state (Gemini)

The app currently uses Google Gemini via @ai-sdk/google. The model in use is gemini-3-flash-preview, and the API key is read from the env var GEMINI_API_KEY.

Gemini is wired in four places — the package entry plus three feature modules that instantiate the provider directly:

File Purpose Lines
packages/ai/index.ts Shared textModel export 1–7
packages/api/modules/mailboxes/procedures/compile-rules.ts Rule compilation (natural-language → structured rule) 244–272
packages/api/modules/mailboxes/lib/rule-evaluator.ts Per-email rule evaluation (AI condition matching) 148–175
packages/api/modules/ai/procedures/rules-assistant.ts AI Assistant chat for building rules 129–133

There is also a stale standalone test file at packages/ai/test-aisdk-google.mjs that should be deleted as part of the migration.

2. Target state (Azure OpenAI)

Replace @ai-sdk/google with @ai-sdk/azure and route all four call sites through a single shared provider in @repo/ai so we don't have to re-instantiate the SDK in each feature module.

Recommended refactor: collapse the three inline provider creations into the shared textModel from @repo/ai. That way we never have to change env-var names in more than one file again.

3. Code changes

3.1 — packages/ai/package.json

  • Remove dependency: @ai-sdk/google
  • Add dependency: @ai-sdk/azure (latest)

3.2 — packages/ai/index.ts

import { createAzure } from "@ai-sdk/azure";

const azure = createAzure({
  apiKey: process.env.AZURE_OPENAI_API_KEY ?? "",
  resourceName: process.env.AZURE_OPENAI_RESOURCE_NAME ?? "",
  apiVersion: "2024-10-01-preview",
});

export const textModel = azure(
  process.env.AZURE_OPENAI_DEPLOYMENT ?? "gpt-4o-mini",
);

export { createAzure } from "@ai-sdk/azure";
export * from "ai";
export * from "./lib";

Note: the old re-export export { createGoogleGenerativeAI } from "@ai-sdk/google" must be removed — it is currently imported by the three feature modules below.

3.3 — packages/api/modules/mailboxes/procedures/compile-rules.ts

  • Replace import: import { createGoogleGenerativeAI, generateText, Output } from "@repo/ai" → import { textModel, generateText, Output } from "@repo/ai"
  • Remove the local apiKey check on GEMINI_API_KEY and the const gemini = createGoogleGenerativeAI({ apiKey }) call.
  • Replace model: gemini("gemini-3-flash-preview") with model: textModel.
  • Update the missing-key error log to reference AZURE_OPENAI_API_KEY instead of GEMINI_API_KEY (or, better, just check that textModel works and let it surface its own error).

3.4 — packages/api/modules/mailboxes/lib/rule-evaluator.ts

  • Same import swap as 3.3.
  • Remove the inline const gemini = createGoogleGenerativeAI({...}) on line 156 and use textModel directly.
  • The model: "gemini-3-flash-preview" string on line 171 (used in a log message) should be replaced with the deployment name or a generic "azure-openai" string.

3.5 — packages/api/modules/ai/procedures/rules-assistant.ts

  • Same import swap as 3.3.
  • Replace the inline provider creation on lines 129–133 with textModel.

3.6 — Delete stale test file

  • Remove packages/ai/test-aisdk-google.mjs.

3.7 — Lockfile

Run pnpm install at the repo root after editing packages/ai/package.json so pnpm-lock.yaml reflects the dependency swap.

4. Azure resources to provision

  1. Azure portal → Create resource → Azure OpenAI. Use the same region and resource group as the zer0email-staging-web App Service if possible to minimize cross-region latency and egress.
  2. Once provisioned, open Azure AI Foundry (formerly Azure OpenAI Studio) → Deployments → Create new deployment.
    • Model: gpt-4o-mini for cost-efficient runs (close substitute for gemini-flash) or gpt-4o for higher quality.
    • Deployment name: e.g. zeromail-staging.
  3. From the resource blade → Keys and Endpoint, copy KEY 1 and note the resource name (the bare name, not the full endpoint URL).

5. Env vars on App Service

Add to zer0email-staging-web → Environment variables:

AZURE_OPENAI_API_KEY       = <KEY 1 from the Azure OpenAI resource>
AZURE_OPENAI_RESOURCE_NAME = <resource name, e.g. zeromail-aoai>
AZURE_OPENAI_DEPLOYMENT    = <deployment name, e.g. zeromail-staging>

Remove (or leave unset): GEMINI_API_KEY.

Heads up — model availability. Azure OpenAI gates some models by region and quota. gpt-4o-mini is broadly available; some reasoning/preview models are not. Verify the chosen model is available in your region before committing to a deployment name.

6. Verification checklist

  1. App boots without errors (no GEMINI_API_KEY is not set logs).
  2. Hit AI Assistant page → send a chat message → response streams back.
  3. Create a new rule via the assistant → verify rule compilation succeeds.
  4. Trigger rule evaluation against an inbound email → verify AI condition matching runs without errors in App Insights.

7. Rollback plan

Revert the commit that swaps the provider; restore GEMINI_API_KEY in App Service env vars. Because the change touches only the AI provider wiring (no schema migrations, no auth changes), rollback is a single revert and a restart.
